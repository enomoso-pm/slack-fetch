# Slack 取得（slack-fetch）

Claude Code と claude.ai の Slack 連携（MCP）だけを使って、Slack のチャンネルの履歴を**抜けなく**手元にためる仕組みです。毎朝の自動取得と、状態を見る Mac のメニューバーのアプリが付いています。

自前の Slack アプリ（Bot やトークン）を登録しなくても使えます。ただし、Slack の管理者が Claude の連携を許可している必要があります。

- **AI に投稿の中身を読ませない・書き写させない**: 取得専用の Claude（Haiku）は、Slack の道具を呼ぶだけです。投稿を含む結果は Claude Code がファイルに置くので、AI は中身を読みません（「見つからなかった」のような、ごく短い返事だけはそのまま返ります）。保存はプログラムが行います
- **何を取るかはプログラムが決める**: チャンネルは1週間ずつ、スレッドは返信のある投稿ごとに取ります
- **毎回照合する**: スレッドの返信数が Slack の表示どおりか、期間に1秒のすき間もないか、読み分けに漏れがないかを確かめます。合わなければ NG で知らせ、次の回で取り直します
- **使いすぎを防ぐ**: 1回の取得の使用量（API 換算）が上限（既定 5 ドル）を超えたら止まります

## 使う前に（必ず読んでください）

これは個人が作った道具で、Slack や Anthropic（Claude）の公式のものではありません。使う前に、次の3つを確かめてください。

- **会社の Slack で使うなら、先に管理者に確かめる**: ワークスペースのデータは、会社（Slack の契約者）のものです。Slack の公式の書き出しも、管理者（Owner・Admin）だけができる機能です。Claude の Slack 連携は管理者が承認・管理するもので、Enterprise プランでは、連携での読み取りが1回ごとに、管理者の見られる記録（監査ログ）に残ります。Slack には、データを大量に読み出す動きを検知して、その人のログインを切る仕組みもあります
- **Slack と Anthropic の決まりを守るのは、使う人**: この仕組みは、自分の Mac で、手を加えていない Claude Code に自分の Claude のプランでログインして、自分が見られるチャンネルを自分の手元にためるためのものです。ほかの人のアカウントで動かしたり、ほかの人に向けたサービスにしたりしないでください（関係する決まりは「気をつけること」）
- **ある日、動かなくなることがある**: Slack や Anthropic の決まり、Claude Code の変更しだいで、動かなくなることがあります。たとえば、`claude -p` の既定の動き方が将来変わる予定があり、その形では claude.ai の連携が使えません

## そろえるもの

| もの | 中身 |
| --- | --- |
| Mac | macOS 14 以上（試したのは macOS 26） |
| Mac の開発用の道具 | ターミナルで `xcode-select --install`（無料）。Xcode が入っていれば不要。python3 とアプリの組み立てに使います |
| Claude Code | Cursor・VS Code の拡張機能か、ターミナル版。claude.ai のアカウントでログインしておきます（拡張機能だけでも動きます） |
| Claude の Slack 連携 | claude.ai の「Customize > Connectors」で Slack をつなぎます（アプリの「はじめの準備」が、ページを開くところから案内します）。Claude の Pro・Max・Team・Enterprise プランで使えます（Team・Enterprise は、組織の Owner が先に有効にします）。Slack 側では、ワークスペースの管理者が Claude の連携を許可している必要があります |
| 日本時間 | 投稿の時刻を日本時間として読み、日付も日本時間で区切ります。ほかの時間帯では試していません |

## はじめ方（Cursor・VS Code の Claude に手伝ってもらう）

Cursor か VS Code で Claude Code が使えるなら、この流れがいちばん簡単です。

1. **取ってくる**: このページの「Code」→「Download ZIP」で取ってきて展開し、できたフォルダを**ホームの直下**（例: `~/slack-fetch`）に置きます（`git clone` でもかまいません。フォルダの名前は何でもかまいません）
   - 「書類」「ダウンロード」「デスクトップ」の中にも置けますが、その場合はアプリがフォルダを読む許可を求めてきます（許可すれば使えます）
   - 取ったデータは、このフォルダとは別に、ホームの直下の `~/Slack取得データ` に入ります（下の「できるもの」）。このフォルダを新しい版に入れ替えても、取ったデータは消えません
   - 2026年10月より前の版を使っていた人は、先に「新しい版にするとき」を読んでください（前のフォルダを消すと、取ったデータも消えます）
2. **開く**: Cursor か VS Code の「ファイル」→「フォルダーを開く」で、そのフォルダを開きます
3. **頼む**: Claude Code の欄で「準備して」と頼みます。Claude が `CLAUDE.md` の手順で、次のところまで手伝います
   - Mac の開発用の道具の確認
   - claude.ai のリンク（Slack コネクタのページなど）を調べ直して、アプリに入れる（リンクは変わることがあるため）
   - アプリの組み立て
4. **アプリを開く（自分で）**: Finder で `アプリ/build/Slack取得.app` をダブルクリックします。「はじめの準備」の窓が出るので、案内どおりに進めます
   - **① Slack をつなぐ**: 「claude.ai の Slack のページを開く」を押す → ブラウザで「Connect to Claude」→ Slack の画面で「許可する」→ アプリに戻って「つながったか確かめる」。アプリが、本当に Slack を読めるかを確かめます（20〜60秒）
   - **② 取るチャンネルを選ぶ**: チャンネル名の一部を入れて Enter を押すと、Slack から探します（20〜60秒。日本語の名前は日本語で）。取りたいチャンネルにチェックを付けます（いくつでも）。取り始める日は、チャンネルができた日が分かればその日、分からなければいちばん古い投稿から推定します（直すこともできます）。「保存して次へ」を押すまでは、何も保存されません
   - **③ 取得を始める**: 「最初の取得を始める」を押します。取り始める日からの分をまとめて取ります。量が多いと、使いすぎ防止の上限か、周の上限（20周）で止まります。もう一度「今すぐ取る」を押せば、続きから取ります
   - ③ の画面か歯車で「Mac の起動時にこのアプリを開く」をオンにすると、毎朝 9:00（変えられます）に自動で取ります（最初の取得のあとから）。Mac がスリープしていた日（ふたを閉じていたなど）は、点検のために一瞬起きたときか、Mac が起きたときに始めます（眠っている間は止まり、起きたら続きを取ります）。途中のスリープで取れなかった分があるときは、アプリが黄色で「スリープで取れなかった分があります」と知らせるので、Mac が起きているときに「もう一度取る」を押してください
   - アプリを Claude に開かせないでください（取得を動かせなくなります。そのときはアプリが気づいて知らせます）
   - アプリは「アプリケーション」フォルダに移してもかまいません。取得の仕組みのフォルダは、組み立てたときの場所を覚えています
   - あとでフォルダを動かしたり名前を変えたりしても、同じ Mac の中なら、アプリが自動で追いかけて「移動していました」と知らせます。元の場所に新しい版を置いたときや、別の場所で組み立て直したときは、新しい版を使います。見つからないとき（ゴミ箱に入れた・外付けのディスクへ移したなど）は、アラートの「場所を選ぶ」か、設定の「取得の仕組みのフォルダ」で選び直してください。見つかるまで、取得はしません
   - あとからチャンネルを足したり外したりするときは、メニューの「Slack とチャンネル…」か、歯車の「取るチャンネル」の「開く…」から、同じ窓を開きます（下の「チャンネルを足す・外す」）
5. **ターミナルで取ることもできます**: エディタのメニューの「ターミナル」→「新しいターミナル」で、次の1行を動かします。最後に「合わないもの 0」と出れば成功です

   ```bash
   caffeinate -i bash 取得係.sh
   ```

   - Claude に頼んで動かすことはできません（Claude Code の中から、別の Claude Code は起動できないため）
   - `caffeinate -i` は、取得の途中で Mac が眠らないようにするためのものです（ふたを閉じると、電池で動いているときはそれでも眠ります。そのときは、取得のまとめとアプリに「途中で Mac がスリープしていました」と出ます）

### 自分の手で始めるとき（ターミナルだけで）

1. 上と同じように取ってきて、ホームの直下に置きます
2. ターミナルで `claude` を開き、`/mcp` と打ちます。一覧に「claude.ai Slack」があり、つながっていれば準備できています
3. 取るチャンネルを書きます

   ```bash
   cd ~/slack-fetch
   mkdir -p ~/Slack取得データ
   cp チャンネル.例.json ~/Slack取得データ/チャンネル.json
   ```

   `~/Slack取得データ/チャンネル.json` には、1チャンネルを1行で書きます

   | 欄 | 中身 |
   | --- | --- |
   | `id` | チャンネル ID（C で始まる英数字）。Slack でチャンネル名を押して開く「チャンネル詳細」のいちばん下にあります |
   | `tag` | 短い呼び名（2〜4文字）。アプリの表示に使います |
   | `name` | 表示用の名前 |
   | `from` | 取り始める日（`YYYY-MM-DD`）。ふつうはチャンネルができた日（「チャンネル詳細」に作成日が出ます）。この日から取ります |

4. 最初の取得: `caffeinate -i bash 取得係.sh`（上の5と同じ）
5. アプリ: `bash アプリ/build.sh` で組み立てて、`open アプリ/build/Slack取得.app` で開きます（`~/Slack取得データ/チャンネル.json` があれば、はじめの準備の窓は出ません。あとは上の4と同じ）

取れるのは、自分の Slack アカウントから見えるチャンネル（社外と共有している Slack コネクトのチャンネルも）です。

## チャンネルを足す・外す

メニューの「Slack とチャンネル…」（または歯車 →「取るチャンネル」の「開く…」）で、はじめの準備と同じ窓が、チャンネルの画面から開きます。

- 足す・✗ で外す・呼び名や取り始める日を変えることができます。**「保存する」を押すまでは、何も変わりません**（✗ で外したものは「保存すると外れます」と残り、「戻す」で戻せます。変えたまま閉じようとすると、保存せずに閉じるかを聞きます）
- **外したチャンネルの取ったデータは消えません**。状況ページの数・グラフと照合に使わなくなるだけです
- 外したチャンネルは「前に取っていたチャンネル」に出ます。「付け直す」を押すと、前の呼び名と取り始める日に戻ります。次の取得では、前に取った分は使い回して、取っていない期間（外していた間）と最近の分だけを取ります（一から取り直しません）
- 取り始める日を前にずらすと、その前の分だけを足して取ります。後ろにずらしても、取ったデータは消えません
- 保存すると、状況ページを数え直します（20秒ほど。Claude は動かしません）。足したチャンネルは、次の取得（「今すぐ取る」か毎朝の自動取得）で取ります

## 新しい版にするとき

取ったデータは、取得の仕組みのフォルダ（このフォルダ）の外の `~/Slack取得データ` にあります。仕組みのフォルダは、新しい版にまるごと入れ替えてかまいません。

**2026年10月より前の版を使っていた人は、先に下の「前の版から新しくするとき」を読んでください。** 前の版は、取ったデータを仕組みのフォルダの中に置いていたので、前のフォルダを消すと、取ったデータも消えます。

1. 新しい版を取ってきます（「Download ZIP」で取ってきて展開する。`git clone` した人は、そのフォルダで `git pull`）
2. 前のフォルダと入れ替えます（別の場所に置いてもかまいません）
3. 新しいフォルダで `bash アプリ/build.sh` を動かして、アプリを組み立て直します（「アプリケーション」フォルダに入れている人は、入れ直します）
4. アプリを開きます。別の場所で組み立て直したときは、アプリがそちら（新しい版）を使います

### 前の版から新しくするとき（2026年10月より前の版）

前の版は、取ったデータを仕組みのフォルダの中（`データ/`。もっと前の版は、一番上の `原本/`・`状態.json` など）に置いていました。新しい版は、そのデータを `~/Slack取得データ` へ引っ越してから使います。

- **前のフォルダは、引っ越しが終わるまで消さないでください**
- 新しいアプリを開くと、前のフォルダのデータを見つけて「引っ越す」を出します。押すと、写して、1つずつ同じか確かめてから切り替えます。途中でうまくいかなくても、前のデータはそのままです（もう一度押せば、やり直します）
- 「引っ越す」が出ないとき（前のフォルダを、アプリが覚えていないとき）は、はじめの準備の窓のいちばん上の「前の版のフォルダを選んで引っ越す…」か、設定（歯車）の「保存先」→「前の版のデータ」の「選ぶ…」で、前のフォルダを選びます（ターミナルなら、新しいフォルダで `python3 slack.py migrate <前のフォルダ>`）
- 前のデータは「データ（引っ越し済み 日付）」という名前で、前のフォルダに残ります。新しい場所で取得できたのを確かめてから、設定（歯車）の「保存先」の「ゴミ箱に入れる…」で片付けます（ゴミ箱を空にするまでは、Finder で戻せます）
- 新しい場所に、すでに別のデータがあるときは、混ぜずに止まります。どちらを使うか決めて、使わないほうを別の場所へ移してから、もう一度動かします
- **はじめの準備は、引っ越してから進めてください**。先に進めると、新しい場所にチャンネルの一覧が書かれて、引っ越せなくなります（前のデータを見つけているあいだは、アプリが取得もはじめの準備も動かしません）

## できるもの

取ったものは、すべてホームの直下の `~/Slack取得データ/` に入ります。取得の仕組みのフォルダ（このフォルダ）の外に置くのは、仕組みを新しい版に入れ替えても消えないように、また、このフォルダを GitHub などに上げても取ったデータが混ざらないようにするためです。

```text
~/Slack取得データ/
├─ チャンネル.json                        取るチャンネル（アプリの「はじめの準備」で選ぶか、自分で書く）
├─ 外したチャンネル.json                  一覧から外したチャンネルの呼び名と取り始める日（付け直すと戻す）
├─ チャンネル候補.json                    はじめの準備で Slack から探したチャンネル（アプリが読む）
├─ 状態.json・取得の記録.jsonl・例外.json   いまの状態と、毎回の取得の結果（アプリが読む）
├─ チャンネル/
│   ├─ general__C0123456789/              1チャンネル1フォルダ（名前__ID）
│   │   ├─ 記録.jsonl                     1投稿1行（下の表）
│   │   └─ 原本/2026-09/ …                Slack から返ってきたそのまま（投稿の月ごと）
│   └─ …（チャンネルの数だけ）
├─ よけた原本/ …                           空で返ってきたが、あとで取り直せた原本（Mac のスリープや一時的なエラーなどで。消さずにここへよける）
└─ 取得ログ/2026-10/ …                     周ごとの一覧・結果・まとめ（月ごと）
```

- チャンネルの名前があとで変わっても、ID で見分けるので困りません（フォルダの名前は最初の名前のまま）
- 計画を立てるときは、そのチャンネルの原本だけを読みます。チャンネルが多くても遅くなりにくい作りです
- アプリから動かした取得係などの出力は、`取得ログ/アプリから動かした記録.log` に書き足します
- iCloud（「書類」「デスクトップ」の同期）や Google ドライブで同期される場所へは動かさないでください。会社のデータが、個人のクラウドに上がります

### 残すもの・消してよいもの

バックアップするなら、`~/Slack取得データ/` を丸ごと写してください。

- 消してよいのは、次の3つだけです
  - `記録.jsonl`（取るたびに、原本から作り直します）
  - `チャンネル候補.json`（はじめの準備で探し直せます）
  - 古い取得ログ（`取得ログ/` の、前の月のフォルダ）
- ほかは消さないでください。とくに `状態.json` は、最後にうまく取れた日を覚えていて、古いスレッドに後から付いた返信を、その日から探します。消すと探す範囲が「2日前から」に縮み、そのあいだの返信を取りこぼします（照合でも気づけません）
- `原本/` は、Slack から返ってきたそのままのもので、手元では作り直せません（Slack 側で消された投稿は、取り直しても戻りません）

`記録.jsonl` には、1投稿を1行で書きます。

| 欄 | 中身 |
| --- | --- |
| `ts` | 投稿の ID（Slack の時刻） |
| `thread_ts` | 返信なら、親の投稿の `ts` |
| `time` | 日時（日本時間） |
| `user_id`・`user_name` | 発言した人 |
| `external_org` | 社外の人なら、その所属 |
| `text` | 本文 |
| `reply_count` | 返信の数（親の投稿） |
| `also_in_channel` | 「チャンネルにも投稿」した返信 |
| `reactions`・`files` | リアクション・添付ファイルの名前 |
| `forwarded_from`・`attachments` | 転送・リンクのプレビュー |
| `raw_file`・`fetched_at` | もとになった原本と、取った時刻 |

## しくみ

```text
[アプリ（毎朝・今すぐ取る）] または [ターミナル]
        │
        ▼
[取得係.sh] 取り残しが無くなるまで、1周ずつ繰り返す
   1. slack.py plan …… まだ取っていない／取り直す呼び出しの一覧を作る
   2. claude -p（Haiku）…… 一覧のとおりに呼ぶだけ。MAX_MCP_OUTPUT_TOKENS=20 なので投稿を含む結果はファイルに置かれ、
        AI は中身を読まない。ファイルを読む道具・コマンドの道具は渡さない
   3. slack.py extract …… Claude Code の作業記録と置かれたファイルから、原本を保存する
        │
        ▼
   slack.py build（原本 → 記録）→ check（照合）→ status（状態.json）→ Mac の通知
```

- 毎日の取得では、直近2週間の週を取り直します（返信の増えや書き直しを拾うため）。前回より後のスレッドの投稿を Slack の検索で探して、古いスレッドに後から付いた返信も拾います
- 取ってある期間は、週の区切り方によらず取り直しません。取り始める日をずらしたときや、外していたチャンネルを付け直したときも、取っていない期間だけを取ります
- 取得係（AI）に投稿が見えたかは、AI の言葉ではなく、プログラムが作業記録で確かめます（ファイルに置かれずその場で返った結果に、投稿が入っていたか）。投稿の無い週の短い返事は、その場で返っても止めません。見えたときは、取れた分を保存してから止めるので、もう一度取れば続きから取ります
- 取得のまとめに出る「取得係の自己申告」は、AI が自分で言った数です（呼んだ数や失敗の数を言い違えることがあります）。正しい数は、原本を数えた「取れたのは」の行です
- 取得の途中で Mac が眠ると、その間は取得が止まり、途中の呼び出しが空で返ることがあります。空で返った分は次の周で取り直します。取り直せた空の原本は、記録を作る前に `~/Slack取得データ/よけた原本/` へ移し（消しません）、照合では NG にしません（`python3 slack.py set-aside`。取得係.sh が毎回動かします）
- 取得の途中で Mac が眠っていた間は、Mac の電源の記録（`pmset -g log`）から調べて、取得のまとめ・アプリ（小窓・状況ページ・取得の記録）・Mac の通知に出します。眠っている間に点検のために一瞬起きただけのときは、続けて眠っていたことにします。アプリから動かした取得では、眠りに入った時刻と起きた時刻を `~/Slack取得データ/取得ログ/アプリから動かした記録.log` にも書きます
- スレッドを頼むと、まれに別のスレッドが返ることがあります（Slack 側のふるまい）。そのときは、次の取得で別の呼び方を試します（3通りまで。当たった呼び方は、取り直しでもまねます）。3通りとも別のスレッドが返ったら諦めて、照合の NG に「取りに行くと別のスレッドが返る」と出します（同じ呼び出しを何周も繰り返さないため）
- 照合（`python3 slack.py check`）で見ること。照合するのは、`チャンネル.json` にあるチャンネルだけです:
  - スレッドの返信数: Slack の表示 = スレッドの見出し = 実際に取れた数
  - 返信があるのに、親の投稿から返信数が読めていないものが無いか
  - 期間の抜け: 取り始める日から最後の取得まで、1秒のすき間も無いか
  - 読み分け: 読めなかった見出しの行や、本文に残った返信数の行が無いか
  - 原本の形: 崩れた原本や、ID の無い投稿が無いか（空で返ってきたが、あとで同じものを取り直せた原本は NG にしません）
- `python3 slack.py status refresh` で、取得の記録を増やさずに状況を数え直せます（アプリが、チャンネルを保存したあとに使います）

### はじめの準備（チャンネル探し.sh）

アプリの「つながったか確かめる」「Slack で探す」「取り始める日の推定」は、アプリが `チャンネル探し.sh` を動かします。取得係と同じく `claude -p`（Haiku）を裏で動かし、Slack の道具を1つだけ渡します。

- **つながったかの確かめ・チャンネル探し**: チャンネル検索の道具を呼び、チャンネルの名前・説明を AI が一覧（JSON）にまとめます。Slack のチャンネル検索が返す形は決まっていないため、ここだけは AI が読みます（投稿は読みません）。AI が書き写した ID と名前は、slack.py が Slack の返したそのままの結果（作業記録）と照らし、そのまま近くに並んで出ているものだけを使います。できた日も、結果に出ている日付と合うときだけ使います
- **取り始める日の推定**（Slack ができた日を返さないとき）: Slack の検索で「その年に投稿が1件でもあるか」を年ごとに、続けて見つかった年の月ごとに確かめ、いちばん古い投稿のある月の1日の、さらに1週間前から取ります。検索の並べ替えの向きには頼りません。結果は取得係と同じくファイルに置かせ、AI には投稿の中身を見せません
- 結果は `~/Slack取得データ/チャンネル候補.json` に書き、アプリが読みます。アプリ自身が書くデータは、取るチャンネルの一覧（`チャンネル.json`・`外したチャンネル.json`）と、状況ページで「既知の例外にする…」を押したときの `例外.json` です（ほかに、動かした記録を `取得ログ/アプリから動かした記録.log` に書き足します。どれも `~/Slack取得データ/` の中）

## 使う量の目安

`claude -p` が出す「API で払ったらいくらか」の目安で数えます。定額のプランなら請求ではなく、利用枠をどのくらい使ったかの目安です。

いちばん多く使うのは最初の取得（取り始める日からの分をまとめて取る）で、チャンネルの数・古さ・投稿の量で大きく変わります。毎日の取得は、前回の続きと直近の見直しだけなので、それよりずっと少なくなります。使った量は、アプリの状況ページ（「今月使った量」と「取得の記録」）で見られます。

## 気をつけること

- **会社のデータを手元にためます**。上の「使う前に」を読んで、会社の決まりと管理者の承認を確かめてください（とくに社外と共有しているチャンネル）
- **関係する決まり**（2026年10月に確かめたもの。変わることがあります）
  - [Slack API Terms of Service](https://slack.com/terms-of-service/api)（2025年10月10日版）: 組織の外に向けてアプリを出す側に、メッセージのまとめての書き出し・長く残る写し・AI の学習への利用を禁じています
  - [Slack MCP server](https://docs.slack.dev/ai/slack-mcp-server): Claude などの AI の連携は、ワークスペースの管理者が承認・管理します
  - [Anthropic の利用規約](https://www.anthropic.com/legal/consumer-terms)・[Claude Code の Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance): プランでのログインは、本人がふつうに使うためのものです。ほかの人に向けた道具やサービスで、プランのログインを使い回すことは認められていません。この仕組みは、使う人自身のログインのまま Claude Code を動かし、ログインの情報を読んだり預かったりはしません
- 取れるのは、自分の Slack アカウントから見えるものだけです
- 2週間より前の投稿が、あとから書き直されたり消されたりしても、記録は取ったときのままです
- 添付ファイルの中身は取りません（名前だけ）
- **チャンネルが多いとき**: 最初の取得の呼び出しは、チャンネルの数と古さに応じて増えます（チャンネルは1週間ごとに1回〈投稿の多い週は数回〉、スレッドは返信のあるものごとに1回）。1回の上限（既定 5 ドル）で取り切れないときはそこで止まり、もう一度動かせば続きから取ります（何回かに分かれます）。取り始める日（`チャンネル.json` の `from`）を新しい日付にすると、その日から後だけを取ります
- アプリの「チャンネルごとの内訳」は3つずつ折り返します。数十チャンネルになると、状況ページは縦に長くなります
- Claude Code の中のふるまい（作業記録・大きな結果をファイルに置く動き）と、Slack 連携が返す形に頼っています。どちらかが変わると、動かなくなることがあります。そのときは照合の NG か「2周続けて1件も取れなかった」で止まります（黙って間違えはしません）
- Claude Code の作業記録は約30日で消えます。取得係.sh は毎周すぐに原本へ移すので、ふつうは気にしなくてかまいません
- 取得係も、自分の `~/.claude/CLAUDE.md`・設定・フックを読み込みます。そこに強い決まりがあると、取得係のふるまいが変わることがあります
- 取り始める日を推定したチャンネルは、Slack の検索に出てくるいちばん古い投稿をもとに取り始めます。検索に出てこない投稿がそれより前にあると、その分は取れません。Slack の「チャンネル詳細」の作成日が分かれば、「Slack とチャンネル」の窓で直してください

## うまくいかないとき

| 出る言葉 | すること |
| --- | --- |
| 取るチャンネルが無い | アプリの「はじめの準備」でチャンネルを選ぶ（はじめ方の4）。ターミナルだけで使うときは `~/Slack取得データ/チャンネル.json` を作る |
| Slack の連携が見つからなかった | claude.ai の「Customize > Connectors」で Slack が「Connected」になっているかを確かめる。つないだ直後は、反映まで数分待ってから「つながったか確かめる」をもう一度押す |
| Slack から失敗が返った | claude.ai のコネクタで Slack を開き、「Reconnect」が出ていれば押す |
| 取り始める日を推定できなかった | 「日付を入れる」から、Slack の「チャンネル詳細」の作成日を入れる |
| モデル「…」が使えなかった | 歯車の「取得に使うモデル」で別のモデルを選ぶか、モデルの名前を入れる |
| 結果がファイルに置かれず、投稿が取得係に見えた | 取れた分は保存してあるので、もう一度取れば続きから取る。何度も出るときは、`~/Slack取得データ/取得ログ/` のまとめを見る |
| 返信を取っていないスレッド（別のスレッドが返ったので…） | もう一度取る。次の取得で、別の呼び方を試します |
| 取りに行くと別のスレッドが返る | Slack 側の食い違いで、3通りの呼び方で試しても取れなかったもの。状況ページの「既知の例外にする…」で例外にする（下の `例外.json`） |
| claude（Claude Code）が見つからない | Claude Code を入れて、ログインする（Cursor・VS Code の拡張機能だけでも動きます） |
| 取得係が Claude のログインを使えなかった | ターミナルで `claude` を開いて、ログインを確かめる。Claude Code を新しくした直後なら、`claude -p` の既定の動き方（bare。ログインも claude.ai の連携も使わない）が変わったのかもしれません（「使う前に」）。そのときは、この仕組みの新しい版を待つか、Claude Code を前の版に戻します（`claude install <版>`） |
| 取得係が2周続けて1件も取れなかった | `/mcp` で Slack 連携がつながっているか確かめる。道具の名前が違うときは、下の `SLACK_TOOLS` を書き換える |
| Claude Code の中から開いたアプリやターミナルでは… | アプリを終了して、Finder か Spotlight から開き直す |
| フォルダを読む許可がありません | システム設定 → プライバシーとセキュリティ → ファイルとフォルダ で「Slack 取得」をオンにする |
| 取得の仕組みのフォルダが見つかりません | アラートの「場所を選ぶ」で、取得係.sh のあるフォルダ（または1つ上のフォルダ）を選ぶ |
| 照合 NG | もう一度取る。続くときは `~/Slack取得データ/取得ログ/` のいちばん新しいまとめを見る |
| 途中で Mac がスリープしていました | 取得の途中でふたを閉じるなどして Mac が眠ると、その間は取得が止まります。空で返った分は取り直すので、照合が OK なら抜けはありません。眠らせたくないときは、取り終わるまでふたを開けておく |
| スリープで取れなかった分があります | 途中で Mac が眠っていて、取得がうまく終わらなかったもの。Mac が起きているときに「もう一度取る」を押す（続きから取ります） |
| 前の場所にデータがあります | アプリの「引っ越す」を押す。ターミナルなら、このフォルダで `python3 slack.py migrate`（前のフォルダが別なら、その場所を後ろに付ける）。写して確かめてから切り替え、前のデータは消しません（上の「新しい版にするとき」） |
| 新しい場所には、すでにデータがあります | どちらを使うか決めて、使わないほうを別の場所へ移してから、もう一度引っ越す |
| 使いすぎ防止の上限・周の上限 | もう一度動かせば、続きから取る |

何度取り直しても数が合わないスレッド（Slack 側の食い違い）は、`~/Slack取得データ/例外.json` に理由を付けて書いておけます。照合のたびに「既知の例外」として表示されます。3通りの呼び方で試して諦めたスレッドは、アプリの状況ページの「既知の例外にする…」からも書けます（例外にしたものは灰色の1行で出て、「戻す」で戻せます）。

```json
[{"channel": "C0123456789", "ts": "1760000000.000000", "reason": "Slack の表示と、実際の返信の数が合わない"}]
```

## 細かい設定

取得係.sh は、次の値を環境変数で変えられます（例: `COST_CAP=3 bash 取得係.sh`）。

| 名前 | 既定 | 中身 |
| --- | --- | --- |
| `COST_CAP` | `5` | 1回の取得で使ってよい量（API 換算・ドル）。アプリの設定でも変えられます |
| `MAX_ROUNDS` | `20` | 1回の取得の周の上限 |
| `BATCH` | `150` | 1周で頼む呼び出しの数 |
| `MODEL` | `haiku` | 取得係のモデル。アプリの設定（歯車）の「取得に使うモデル」でも変えられます（チャンネル探しにも効きます）。`haiku`・`sonnet`・`opus` は、その系列のいちばん新しい版を使います。Sonnet・Opus は、使う量（API 換算）が Haiku の数倍です。使えなくなったら、別のモデルを選ぶか、モデルの名前を入れます |
| `SLACK_TOOLS` | `mcp__claude_ai_Slack__` | Slack の道具の名前の頭。claude.ai の連携と違うつなぎ方をしているときは、`/mcp` で道具の名前を確かめて、取得係.sh と チャンネル探し.sh のこの行を書き換えます（claude.ai の連携以外では試していません） |
| `NOTIFY` | `1` | `0` にすると、Mac の通知を出しません |
| `SPILL_TOKENS` | `20` | Slack の結果をファイルに置く大きさ（トークン。Claude Code の `MAX_MCP_OUTPUT_TOKENS` として渡します）。これより大きい結果はファイルに置かれ、AI には置き場所だけが返ります。前は `100` で、投稿1つだけの短い週が AI に見えて止まることがありました。おかしいときは `SPILL_TOKENS=100` で前の動きに戻せます（チャンネル探しの、取り始める日の推定にも効きます） |
| `CLAUDE_BIN` | `claude` | Claude Code の場所。`claude` コマンドが無ければ、Cursor・VS Code の Claude Code の拡張機能に入っている本体を使います |
| `SLACK_FETCH_DATA` | `~/Slack取得データ` | 取ったデータの置き場所。試しのとき用です（アプリはこの値を知らないので、ふだん変えると、アプリとターミナルでデータが2か所に分かれます） |

## ファイル

| ファイル | 中身 |
| --- | --- |
| `CLAUDE.md` | Cursor・VS Code などで、このフォルダを開いた Claude への手順書（「準備して」と頼んだときの進め方） |
| `取得係.sh` | 取得の本体（計画 → 取得 → 保存を繰り返し、最後に照合） |
| `チャンネル探し.sh` | はじめの準備の「つながったか確かめる」「Slack で探す」「取り始める日の推定」（アプリが動かす） |
| `slack.py` | 計画・原本の保存・記録づくり・照合・状態の書き出し・チャンネル探しの照合（Python の標準の部品だけ） |
| `チャンネル.例.json` | チャンネルの書き方の見本（写して `~/Slack取得データ/チャンネル.json` にする） |
| `~/Slack取得データ/` | 取ったもの・設定・状態（このフォルダの外。取得のときにできる。中身は「できるもの」） |
| `アプリ/` | メニューバーのアプリ（`Sources/`・`Info.plist`・`build.sh`）。はじめの準備（「Slack とチャンネル」）の窓は `Sources/Setup.swift` |
| `アプリ/リンク.json` | はじめの準備の窓で開く claude.ai などのリンク。組み立てるときにアプリに入る（準備のときに Claude が調べ直す） |

アプリの見た目と動きは、開かずに確かめられます（`アプリ/build/Slack取得.app/Contents/MacOS/SlackFetch` に付けて動かす）。`--snapshot <書き出すフォルダ>` で画面を画像に書き出し、`--test-base`（フォルダの追いかけ・前のデータ探し）と `--test-setup`（チャンネルの付け外し・既知の例外・引っ越しの見張り）・`--test-chart`（グラフにマウスを乗せたときの日の見分け）で自分を試します。どれもデータを書き換えず、取得も動かしません（`--snapshot` は自分のデータを読みません。自分のデータで描くときは `-dataDir ~/Slack取得データ` を付けます）。
